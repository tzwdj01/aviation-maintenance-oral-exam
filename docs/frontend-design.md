## 1. 前端架构

React + TypeScript + Vite 使用按业务域组织的 `features/`：`auth`、`exams`、`question-bank`、`vocabulary`、`review`、`reports`。API Client 集中管理认证、`request_id`、幂等键、错误转换和轮询；录音封装为独立模块，页面不直接处理浏览器媒体 API 细节。严格 TypeScript，禁止 `any` 逃逸关键考试状态。

服务端状态是权威来源，名称严格引用 `ExamAttemptState` 与 `AttemptItemState`。浏览器保存最小的会话恢复信息（如 attempt ID），重载后调用考试详情接口恢复；`RECORDING` 仅是当前页面 UI，不在本地持久化音频或评分结果。

## 3. 考试工作台关键交互

- 固定显示：当前题号/总题数、进度、问题文本、TTS 播放/重听、录音计时、麦克风状态、网络状态和“处理中”状态。
- 录音完成后先显示上传与 ASR 进度；允许在 ASR 未采纳前重新录音。重录创建新回答记录，不覆盖旧音频。
- 页面刷新后恢复当前题与处理进度。网络离线时禁止提交并提示恢复连接；已提交请求依据幂等键查询结果。
- 正式模拟考试过程中，考生不得看到得分、知识点覆盖、Critical Error 或追问原因。只在合规范围内展示最终报告。
- TTS 失败显示题干文字及“重新播放”按钮；不因语音失败阻止答题。

## 4. 复核与可访问性

复核页应采用时间线：题目/计划快照 → 主答音频/全部 ASR/当前采用文本与词典版本 → 可高亮验证的 EvidenceSpan → 四个 Pass → 追问链 → 最终评价 → ReviewDecision/Item。AI 建议和人工最终结果并排显示，并在所有人工覆盖项旁展示原值、修改者、理由与时间。

控件支持键盘操作、清晰的录音状态文本、颜色之外的状态标识及可读的错误提示。音频下载/播放必须使用短期授权 URL，前端不保存 MiMo 凭据。
