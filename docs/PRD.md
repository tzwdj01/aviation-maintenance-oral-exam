# 航空维修放行人员 AI 口试系统 PRD

> Status: ACTIVE
> Owner: 产品负责人
> Last Reviewed: 2026-08-16（Phase 0 Governance Baseline）
> Source of Truth For: 产品需求、角色、功能范围、验收标准、成功指标

## 1. 产品概述

本系统用于模拟航空维修放行人员口试。考生通过语音作答，系统将回答转写、按预先维护的结构化评分标准评分，并针对知识缺口进行有限次追问，最终输出可人工复核的考试结果。

系统是口试训练与辅助评估工具；在未完成适用资质、题库治理、评估验证及人工复核流程前，不应用作独立的法定放行授权依据。

## 2. 目标与非目标

### 2.1 目标

- 以语音完成“出题—回答—评分—追问—结果”的完整闭环。
- 让每道题的评分依据可追溯、可版本化、可人工复核。
- 将关键安全错误（Critical Error）与一般得分独立处理。
- 让后端统一管理 MiMo ASR、TTS、LLM 调用，前端不接触 API Key。
- 保存原始音频、ASR 文本、LLM 评分、追问及最终结论。

### 2.2 非目标（第一阶段）

- 不开发无人值守的放行资质认定或自动发证能力。
- 不让 LLM 创建、修改或推断标准答案与评分标准。
- 不在前端直接调用 MiMo API。
- 不实现远程监考、身份核验、防作弊或学习内容生成。
- 不以实时流式 ASR 为第一阶段前提；先支持逐段上传和转写。

## 3. 用户与角色

| 角色 | 主要诉求 | 权限边界 |
| --- | --- | --- |
| 考生 | 开始口试、听题、语音作答、查看本人结果 | 仅访问本人考试与结果 |
| 考评员 | 复核 AI 评分、填写人工结论、导出结果 | 可访问被授权的考试记录与审计材料 |
| 题库管理员 | 维护题目、结构化标准答案与版本 | 不能通过考试界面篡改已使用版本 |
| 系统管理员 | 管理用户、角色、系统配置与密钥部署 | 不应通过普通页面读取明文密钥 |

## 4. 核心用户流程

1. 考生选择考试计划并开始一次考试。
2. 系统选择当前有效题目版本，创建考试快照，锁定题目与评分规则。
3. 系统生成题干语音（TTS）并展示文本；考生可按规则重听。
4. 考生录音并提交一个回答片段。
5. 后端保存音频，调用 ASR 获取转写文本，并保存完整供应商响应。
6. 后端将**锁定的评分标准**、题目、转写文本传给 LLM，要求返回约定 JSON。
7. 系统独立记录 Critical Error 判断和评分结果，校验 JSON 后保存。
8. 若 LLM 建议追问且追问次数少于 2 次，系统生成与缺失知识点有关的追问，重复步骤 3–7。
9. 题目完成后进入下一题；所有题目结束后生成考试汇总结果。
10. 考评员可查看题目快照、音频、转写、AI 输出和人工复核记录。

考试开始前，考生/考评员选择机型与授权类型；系统按计划从符合条件的已发布题目版本随机组卷。考试结束后，除总分外生成能力分析报告，区分首次独立回答能力、追问后的最终掌握度及追问依赖度。

## 5. 功能需求

### 5.1 考试与题目

- 考试计划应定义题目范围、题目数量、及格规则和是否允许重听。
- 每次考试必须引用不可变的题目版本和评分规则快照。
- 支持主问题及最多 2 次追问；追问只补充当前题目的评估，不得替换主问题标准。
- 考试和题目状态必须严格采用 [EXAM_STATE_MACHINE.md](EXAM_STATE_MACHINE.md) 定义的 `ExamAttemptState` 与 `AttemptItemState`；本 PRD 不维护第二套状态枚举。

### 5.2 语音交互

- 前端采集回答音频并上传至后端；后端生成受控的音频访问地址。
- TTS 失败时必须保留题干文本并允许文本模式继续。
- ASR 失败、低置信度或空转写时，系统必须允许重新录音或转人工处理，不得直接给出负面判定。
- 音频格式、最大时长和大小由服务端校验并配置化。
- ASR 必须同时保存原始文本和术语标准化文本；默认以标准化文本评分，但复核界面始终显示原始文本。

### 5.3 评分与追问

- 每道题必须维护 `must_have_points`、`important_points`、`critical_errors` 三类标准。
- LLM 只能将考生回答映射到输入的标准；不得判断未在规则中定义的“标准答案”。
- LLM 分析输出必须是可校验的结构化 JSON，包含点状态、缺失点、可验证证据、Critical Error 与追问建议；所有正式分数仅由服务端规则引擎计算。
- V1 对同一回答执行独立的语义覆盖、Critical Error、回答质量/风险意识、追问决策四阶段分析；不得仅为减少模型调用而合并阶段，除非通过验证证明评分可靠性不降低。
- Critical Error 必须独立判定、独立保存、独立影响结果。若命中，默认该题为不通过并触发人工复核；最终考试规则由考试计划配置。
- 单题最多追问 2 次。追问必须引用缺失知识点 ID，并保留触发原因。

### 5.4 审核与审计

- 保存每一次原始音频、ASR 文本/原始响应、LLM 请求版本/原始响应、解析结果、追问和状态变更。
- 人工复核不得覆盖 AI 原始结论；应保存独立的复核结论、理由、操作者和时间。
- 成绩报告应区分 AI 建议结果、人工复核状态和最终结果。

### 5.5 能力报告

- 每题输出 `initial_response_score`、`final_mastery_score`、`prompt_dependency`、关键缺失点、Critical Error 与复核状态。
- `prompt_dependency` 使用 A–D：A 为无需追问即可完整回答；B 为一次轻度追问后完整；C 为需明显追问才完整；D 为追问后仍未掌握。
- 考试报告按核心技术、程序意识、判断与处置逻辑、风险意识、表达完整性汇总，并给出薄弱知识点和重点复习建议。

## 6. 验收标准（第一阶段）

- 从开始考试到结果页可完成至少一个端到端的模拟口试流程。
- 每一题均能在复核页面看到题目版本、评分规则快照、回答音频、ASR 文本与 AI 原始 JSON。
- 当 LLM 返回非约定 JSON 或无可验证 EvidenceSpan 时，系统拒绝自动定分、记录失败原因并转为可重试/待复核状态。
- 任一题追问次数不超过 2 次，且追问来源可追溯至缺失知识点。
- 前端构建产物、网络请求和客户端配置中均不包含 MiMo API Key。
- SQLite 开发环境与 PostgreSQL 生产环境使用同一 SQLAlchemy 模型与 Alembic 迁移路径。

## 7. 成功指标

- 评分可复核率：已完成题目中，审计材料齐全的比例达到 100%。
- 结构化输出有效率：LLM 首次输出可通过 schema 校验的比例。
- 人工改判率：人工复核后与 AI 建议结果不同的比例，用于校准题库和提示词。
- 语音可用率：成功得到可用转写的回答片段比例。
- 完成率：开始考试后正常完成的比例。

V1 不设置模型调用成本或 Token 使用预算。质量排序为：评分准确性、Critical Error 检出率、动态追问质量、ASR 专业术语识别、TTS 自然度、考试可追溯性、人工可复核性。不得为节省配额使用低质量模型替代方案，或以减少调用次数为目标牺牲上述质量。

## 8. 第一阶段范围与待确认事项

第一阶段建议交付：人员基本信息、机型/授权类型选择、登录和角色、题库/规则/词典版本、随机组卷、可恢复的单套考试、非流式录音上传、TTS/ASR、术语标准化、四阶段结构化评分、有限追问、整题最终评价、结果/能力分析报告、人工复核和完整审计日志。

第一阶段明确不包括：人脸/视频/摄像头监考、移动端和微信小程序、自动联网搜索答案、自动生成正式标准答案、自动决定授权资格、AMM/MEL 全文 RAG、PAKB 集成、知识图谱、Voice Clone、复杂 Agent 系统、多模型供应商切换及 Token 成本优化。架构应为未来 RAG 和法规影响提示保留版本化扩展点，但不得自动改写题库。

待人工确认：首批适用机型/规章范围、题库来源和业务审核责任人、各维度及 `partial` 覆盖的精确权重、考试及题目通过阈值、Critical Error 对整场考试的最终影响、随机组卷规则、报告对考生的可见粒度、术语词典审核机制、音频/审计资料保留期限、认证方式及与既有培训系统的集成范围。

## 10. 主要技术风险

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| ASR 对航空术语/口音误识别 | 误判答案或错误触发关键错误 | 建立领域词表与金标音频集；低置信度重录/人工复核；保留原音频 |
| LLM 结构化输出不稳定或幻觉 | 评分不可复现、超出规则 | 强 schema 校验、仅允许 rubric ID、服务端重算、失败不自动定分 |
| Critical Error 误报/漏报 | 影响安全与公平性 | 独立规则、证据要求、强制复核策略、持续金标校准 |
| 模型延迟、配额或服务故障 | 口试中断或结果延迟 | 超时/退避/限流、任务状态、TTS 文本回退、调用可观测性与可替换适配器 |
| 音频及考试资料泄露 | 隐私与合规风险 | 受控存储、短期 URL、最小权限、加密与保留/删除策略 |
| SQLite 与 PostgreSQL 行为差异 | 迁移或并发问题 | 使用方言兼容类型、Alembic 迁移测试、上线前 PostgreSQL 集成测试 |
